# ScarlettEdge Architecture

**ScarlettEdge** (a clean-room high-level emulation fork of [Freminet/ScarlettX](https://github.com/Freminet/ScarlettX)) executes native **Xbox Series X|S (`XboxGen9` / `Scarlett` Game Core)** x86-64 PE32+ titles on Windows 10/11 x64 without CPU translation, intercepting the Xbox OS, GDK runtime, unified memory, DirectStorage, audio, input, and `d3d12_xs` / `xg_xs` graphics boundary.

---

## 1. Execution & Module Loading Pipeline

1. **Manifest & Container Discovery (`src/loader/game_config.cpp`, `src/runtime/emulator.cpp`, `src/loader/package_vfs.cpp`):**
   - Parses `MicrosoftGame.Config` (`TargetDeviceFamily` = `XboxGen9` / `Scarlett`), extracts `TitleId` and primary executable metadata, maps virtual `G:\` via `DefineDosDeviceA` (`src/runtime/virtual_drive.cpp`) with crash-safe cleanup markers, and mounts any `.xvd` / `.xvc` volumes (using `--volume-key` / `SCARLETTX_VOLUME_KEY` when encrypted).
2. **In-Process PE64 Mapper (`src/loader/pe_mapper.cpp`, `src/loader/guest_modules.cpp`):**
   - Maps the guest `.exe` into process memory, applies `IMAGE_REL_BASED_DIR64` / `HIGHLOW` relocations, registers `.pdata` exception unwind tables (`RtlAddFunctionTable`) so guest C++ exceptions unwind cleanly, binds implicit TLS (`TEB->ThreadLocalStoragePointer` slot 0 and dynamic `_tls_index` callbacks), and isolates guest `atexit` tables.
3. **Two-Tier DLL Precedence Policy:**
   - **System / Hardware HLE DLLs (Shim-First):** `xgameruntime.dll` (`xmem.dll`), `d3d12_xs.dll`, `xg_xs.dll`, `AcpHal.dll`, `xcrdapi.dll`, `dstorage_xs.dll`, `xaudio2_9.dll`, `GameInput.dll`, `XboxBvhBuilder.dll`, `kernelx.dll`, `xvc_crypto.dll`, `xbox_codecs.dll`, `xsapi.dll`, `xs2_lifting.dll`, `vulkan_backend.dll`, and `pixevt_stub.dll` always resolve from ScarlettEdge's shim directory.
   - **Shared Runtime Core (`scarlettx_core.dll`) & All Package DLLs:** `scarlettx.exe` and all 22 HLE DLLs link a single shared `scarlettx_core.dll`, sharing process-wide module tables, `PackageVfs::Global()` Win32 `G:\` file hooks, and isolated guest `atexit`/command-line/`ExitProcess` state. Any non-system DLL shipped inside the game directory (middleware, Oodle, Wwise, engine modules) loads from the package directory first, falling back to ScarlettEdge's HLE shims (`Bink2Scarlett.dll`, `amd_fidelityfx_*`, `libHttpClient.GDK.dll`, `XCurl.dll`) when absent.
   - **Unresolved Imports (`src/loader/stub_thunk.cpp`):** Any missing named or ordinal import receives an executable x86-64 thunk that captures register arguments, logs diagnostics, and returns a configurable status value.

## 2. Graphics, Shaders, & Texture Layout (`d3d12_xs`, `xg_xs`, `xs2_lifting`, `vulkan_backend`)

- **COM Vtable Isolation (`src/shims/d3d12_xs_shim.cpp`):**
  - Real Scarlett titles never receive raw Windows `ID3D12*` COM pointers; every interface (`Device`, `CommandQueue`, `GraphicsCommandList`, `Resource`, `Heap`, `DescriptorHeap`, `Fence`, `CommandAllocator`, `RootSignature`, `PipelineState`, `StateObject`) uses a ScarlettEdge-owned Xbox vtable layout supporting SDK versions `0x20001` through `0x20006` (including the `+4` command-list slot shift at slot `>= 28` and the `+2` SDK `0x20004+` shift).
  - Resource and root-signature proxies are unwrapped across legacy barriers (`ResourceBarrier`), D3D12 Enhanced Barriers (`ID3D12GraphicsCommandList7::Barrier`), DXR `CreateStateObject` subobjects, Variable Rate Shading (`ID3D12GraphicsCommandList5::RSSetShadingRate` / `RSSetShadingRateImage`), sparse 64 KB `ReservedResource` + `UpdateTileMappings` / `CopyTileMappings`, `ID3D12Device8::CreateSamplerFeedbackUnorderedAccessView`, `ExecuteIndirect` GPU count buffers, and autonomous GPU Producer→Consumer Work Graphs.
- **Zero-Lag Guest Textures, `CreatePlacedResourceX`, `XG` MSAA & RDNA2 `DCC`/`HTILE` (`src/shims/d3d12_xs_shim.cpp`, `src/gpu/xg_layout.cpp`, `src/shims/xg_xs_shim.cpp`):**
  - On Xbox's unified memory architecture, titles write cooked swizzled texels directly to `ID3D12Resource::GetGPUVirtualAddress()` or place resources directly onto `KernelX` GPU VAs via `CreatePlacedResourceX` (slot 74). ScarlettEdge tracks dirty pages via `MEM_WRITE_WATCH` (and fast 64-bit subresource hashing for `MapViewOfFile3` section aliases), deswizzles modified subresources via `xg_layout` (`4KB_S`, `256B_S`, `64KB_S/D/Z_X/R_X` with 64 KB packed mip-tails, 2D arrays, CubeMaps, `2x/4x/8x MSAA` disjoint sample planes, and 3D volumes via `XGCreateTexture3DComputer`), decodes RDNA2 `DCC` (`XGDecompressDccSurface`) and 8x8 `HTILE` hierarchical depth (`XGDecompressHtileDepth`), and batches uploads in a single copy submission.
- **Shader Translation, RDNA2 Lifting, & Live Vulkan 1.3 / KHR Ray Tracing (`src/gpu/shader_ir.cpp`, `src/gpu/xs2_lifting_shim.cpp`, `src/gpu/vulkan_backend_shim.cpp`):**
  - Standard DXBC/DXIL shaders containing Xbox-private chunks (`XBOX`, `XS2M`, `XDBG`, `XBIN`) are stripped across `CreateGraphicsPipelineState`, `CreateComputePipelineState`, `CreatePipelineState` stream PSOs, and DXR `CreateStateObject` libraries, re-signing SM 6.x DXIL containers via Windows `dxil.dll` (`IDxcValidator`) or recomputing SM 5.0 DXBC modified-MD5 checksums.
  - Precompiled RDNA2 (`XS2\0` and stripped `XS2M`/`XBIN` with Xbox `SPI_SHADER_PGM_RSRC*` headers) shaders are decoded across 32-bit/64-bit/literal/DPP/SDWA/`VOP3P`/`FLAT`/`MTBUF`/NSA-`MIMG` encodings and lifted with structured loop/selection CFG into **both** (1) signed SM 6.6 bindless (`ResourceDescriptorHeap[]`) DXIL / SM 5.0 DXBC executed natively by host D3D12, and (2) Vulkan-1.3-compliant SPIR-V 1.5 modules executed on hardware `VkComputePipeline` queues (`VulkanXsDispatchComputeSpirv`), alongside hardware-backed `VK_KHR_acceleration_structure` + `VK_KHR_ray_tracing_pipeline` (`vkCmdTraceRaysKHR`).

## 3. Unified Memory, Storage, Crypto, & Runtime Services

- **Unified Memory & Physical Aliasing (`src/kernel/kernelx_shim.cpp`):**
  - Uses `CreateFileMappingW` + `VirtualAlloc2` (`MEM_RESERVE_PLACEHOLDER` with `MEM_ADDRESS_REQUIREMENTS` for guaranteed 64 KB and 2 MB large-page alignment) + `MapViewOfFile3` so multiple CPU virtual addresses (`KernelXCreateMemoryAlias`) map coherently onto the same physical pages while maintaining CPU VA ↔ GPU VA translation.
- **Containers, Crypto, & DirectStorage (`src/loader/xvd_container.cpp`, `src/loader/xvc_crypto.cpp`, `src/shims/dstorage_guest.cpp`):**
  - `aes_xts_cng.h` dynamically binds Windows `bcrypt.dll` for cached-key FIPS-197 AES-128/256-XTS (including IEEE 1619 ciphertext stealing), AES-CBC/CTR transforms, and chunked >4 GiB FIPS 180-4 SHA-256 / HMAC-SHA256 verification. `XvdContainer` supports retail `msft-xvd` v3 headers (`0x284+`), `0xAA` (170-page) Merkle hash-tree de-interleaving, `XvcRegionHeader[]` (`KeyId = 0xFFFF` unencrypted metadata + CIK keyring), and both read-only **NTFS** (`$MFT` resident/runlist `$DATA` + `INDX` directory B-trees) and legacy `GDFX` filesystems across persistent overlapped file handles.
  - Real titles import `xcrdapi.dll` (`dstorage_guest.cpp`) or `dstorage_xs.dll` (`dstorage_xs_forward.cpp` -> `dstorage.dll`), executing concurrent `FILE_FLAG_OVERLAPPED` reads with `PackageVfs::Global()` fallback, spec-compliant RFC 1951 DEFLATE / RFC 1950 Zlib, official DirectStorage 32-lane SIMD bit-interleaved `GDeflate` (`0x04 0xFB`) in both C++ and HLSL `cs_5_0` GPU compute (`DStorageDecompressGpuCompute`), `BCPack` BC1–BC7 GPU block codecs, and direct `CopyTextureRegion` swizzled texture streaming.
- **GDK 2022–2026 Runtime, WinRT, Retail XMA2/Bink2 Media, & GPU Diagnostics (`src/shims/xgameruntime_shim.cpp`, `src/shims/xsapi_shim.cpp`, `src/shims/xaudio2_shim.cpp`, `src/shims/bink2_scarlett_shim.cpp`, `src/shims/d3d12_xs_shim.cpp`):**
  - Full `XTaskQueue` / `XAsync` engine, GDK 2022–2026 `QueryApiImpl` COM tables (`XStore` licensing, `XPackage` DLC enumeration/mounting, CNG HMAC-SHA256 `XBL3.0` JWT signing), WinRT `RoActivateInstance` / `RoGetActivationFactory` `IInspectable` COM broker, persistent `XGameSave` & `XblTitleStorage`, and `HCWebSocket` RTA/PlayFab offline + live `WinHttpWebSocket` transport.
  - Retail 2048-byte `XMA2` multi-stream bitstream parser + Princen-Bradley TDAC `IMDCT` ($N=128$) audio decoder (`52`-byte `0x0166` `XMA2WAVEFORMATEX` guest COM voice bridge), ITU-R BS.775 `5.1`/`7.1` downmix + `X3DAudio` 3D spherical panning/Doppler, host `System32\xaudio2_9.dll` `CreateFX` (`CLSID_FXReverb`, `FXEQ`, `FXMasteringLimiter`), `KB2` frame-offset YCbCr 4:2:0 video decode + QPC A/V PTS lip-sync, and 64-slot GPU stability breadcrumbs + 256-frame QPC `min`/`avg`/`p99`/`max` profiler (`D3D12XboxGetGpuStabilityReport`).
- **4-Part Flight-Recorder Diagnostic Suite (`include/scarlettx/core/flight_recorder.h`, `src/core/flight_recorder.cpp`):**
  1. **Lock-Free Process-Wide Ring Buffer:** 4096-slot MPMC ring buffer inside shared `scarlettx_core.dll` + bounded deduplicated miss registries capturing `StubThunk` missing imports (with exact guest caller RVA), unhandled COM `QueryInterface` IIDs, unimplemented COM vtable slots, WinRT runtime class activations, and `G:\` VFS / DirectStorage file misses.
  2. **Vectored Crash Handler (`VEH`/`SEH`) & x64 Stack Unwinder:** Captures fatal guest hardware/fail-fast exceptions (filtering benign C++ `throw`, `SetThreadName`, `OutputDebugString`, and `GuestExitProcess` unwinds), walks `.pdata` unwind tables via `RtlLookupFunctionEntry` / `RtlVirtualUnwind`, resolves both mapped guest PE64 Ghidra RVAs (`0x140000000+RVA`) via lock-free seqlock module snapshots and host DLL RVAs, and writes `crash_report_<pid>_<seq>.json`/`.txt`.
  3. **GPU DRED & Failing Shader/PSO Dumper:** Enables `ID3D12DeviceRemovedExtendedDataSettings` auto-breadcrumbs + page-fault VA tracking before `D3D12CreateDevice`, extracts `ID3D12DeviceRemovedExtendedData1` + 64-slot `d3d12_xs` breadcrumbs on TDR (`gpu_dred_report_*.json`), and dumps bounded raw Xbox DXBC/DXIL/`XS2` + translated `.dxil` + `_meta.json` artifacts on PSO/RootSignature/StateObject failures.
  4. **Progress-Heartbeat Hang Watchdog & CLI Telemetry:** Background watchdog monitors `BeatProgress` heartbeats across `PresentX`, `ExecuteCommandLists`, `WaitFrameEventX`, `XTaskQueue`, and DirectStorage, sampling stalled thread `RIP`/`RSP`/stack return candidates (`hang_snapshot_*.json`/`.txt`) with zero allocations while threads are suspended, controlled via `--flight-recorder [dir]` and `--hang-timeout <sec>` (`flight_summary.json`/`.txt`).
